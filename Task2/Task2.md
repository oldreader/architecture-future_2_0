Текущее решение - монолит
- 
Для декомпозиции будем использовать DDD. Выдели основные домены:
1) Домен управления клиентами
2) Домен управления клиниками
3) Домен платежей и финансовой истории
4) Домен медицинскими данными клиентов 

### Сценарий 1 для домена управления медицинскими данными клиентов 
Получаем сырые данные, которые потом очищаем в airflow и помещаем в универсальный интерфейс хранения и доступа Dremio. 
Этим сценарием мы снижаем нагрузку на Microsoft SQL-сервер для всех ELT преобразований

### Сценарий 2 для преобразования медицинских данных клиентов
Читаем готовые преобразованные данные из Dremio с помощью datahub. Datahub создаёт высокоуровневую абстракцию для тегирования данных с помощью datahub-actions,
и создания различных представлений для аналитиков.
